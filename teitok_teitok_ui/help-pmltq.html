PML-TQ Search Guide

PML-TQ is a query language for searching annotated trees rather than flat token sequences. It is especially useful for corpora with syntactic, dependency, constituency, or other hierarchical annotation. Where CQL usually asks “which tokens match this sequence?”, PML-TQ asks “which nodes in the tree satisfy this structural pattern?”.

Purpose Of PML-TQ

PML-TQ is used to describe graph- or tree-based relationships between annotated nodes. A query can search for a single node with certain features, but it can also describe parent-child relations, descendants, siblings, nested conditions, and named variables that are reused later.

Typical uses include:

  • finding nodes with a certain annotation, such as upos="NOUN"
  • finding a node that has a child, parent, or descendant of a certain type
  • binding nodes to variables and later referring to those variables
  • searching for syntactic patterns rather than surface token sequences
  • returning specific bound nodes or grouping results over them

Basic Node Queries

The basic unit in PML-TQ is usually a node. Many corpora distinguish node types, such as a-node, m-node, or w-node. A simple query often starts by binding one variable to one node description.

$a := [upos="NOUN"];

This means: bind a node to the variable $a if it has upos="NOUN".

Depending on the treebank, the available fields may include attributes such as upos, xpos, deprel, lemma, form, or corpus-specific structural or semantic annotations.

Node Types

Some corpora require or allow you to specify the node type explicitly.

a-node $a := [upos="NOUN"];
w-node $w := [form="interesting"];

Use the node types that exist in your corpus. Some corpora expose only one major node layer; others distinguish surface tokens, analytical nodes, tectogrammatical nodes, and so on.

Field Constraints

Inside square brackets, you can constrain the values of node attributes.

[upos="NOUN"]
[lemma="go"]
[deprel="amod"]

Negative and alternative conditions are also common.

[upos!="NOUN"]
[upos="NOUN" | upos="PROPN"]

As in many query languages, the exact operators and the exact field inventory depend on the treebank and the PML-TQ environment.

Variable Binding

A central feature of PML-TQ is assigning nodes to variables with :=.

$a := [upos="NOUN"];
$b := [upos="ADJ"];

Once a variable has been bound, later parts of the query can refer to that same node.

This is one of the main differences from simple token-sequence querying: the query often describes several related nodes, each with its own role in the pattern.

Structural Relations

PML-TQ can express relations such as child, parent, descendant, ancestor, or sibling. A common pattern is to constrain one node by requiring that a related node satisfy another condition.

$a := [upos="NOUN", child [upos="ADJ"]];
$a := [upos="VERB", parent [upos="NOUN"]];
$a := [upos="NOUN", descendant [deprel="amod"]];

These examples mean, roughly:

  • a noun with an adjectival child
  • a verb whose parent is a noun
  • a noun that has some adjectival modifier somewhere below it

Nesting Conditions

One structural condition can itself contain another. This makes it possible to express multi-step tree patterns directly.

$a := [upos="NOUN", child [upos="ADJ", child [upos="ADV"]]];

This looks for a noun with an adjectival child, where that adjective itself has an adverbial child.

In practice, nested tree patterns are one of the main reasons to choose PML-TQ rather than a token-sequence language.

Named Variables In Larger Queries

You can bind multiple variables in the same query so that different matched nodes can later be returned, highlighted, grouped, or used as anchors.

$a := [upos="NOUN", child [upos="ADJ", child $b := [upos="ADV"] ] ];

Here $a is the noun and $b is the adverb nested under the adjective. A result may therefore contain multiple important matched nodes that are not adjacent in the surface token order.

Why PML-TQ Results May Be Discontinuous

Unlike a flat token query, a tree query often matches several nodes that are structurally related but not next to each other in the sentence. For example, a parent node and a distant descendant may belong to the same match even if many unrelated surface tokens occur between them.

This is why a simple KWIC display is not always ideal for PML-TQ results. Depending on the interface, it may be better to show:

  • the whole sentence or structural region
  • a span from first matched token to last matched token
  • an anchor-KWIC centered on one especially important bound node

Common Search Examples

A noun node:

$a := [upos="NOUN"];

A noun with an adjectival child:

$a := [upos="NOUN", child [upos="ADJ"] ];

A verb whose parent is a noun:

$a := [upos="VERB", parent [upos="NOUN"] ];

A noun with an adjective that itself has an adverb child:

$a := [upos="NOUN", child [upos="ADJ", child $b := [upos="ADV"] ] ];

A node constrained by a dependency relation:

$a := [deprel="nsubj"];

Fields And Paths

In many PML-TQ environments, fields can be addressed directly, and sometimes path-like references are allowed. You may see expressions such as:

[lemma="go"]
[m/tag="N.*"]
$a.functor = "ACT"

The exact syntax varies by corpus model, node layer, and implementation. When in doubt, check which fields actually exist for the nodes in your corpus.

Output-Oriented Clauses

Some PML-TQ environments support additional clauses for returning and organizing results, for example for, give, sort, by, count, group, freq, or tabulate. For example:

$a := [upos="NOUN"];
for $a.lemma give $1, count()

Whether these are available depends on the backend and on how much of the wider PML-TQ ecosystem the current interface exposes. Some interfaces support only the core structural search, while others also support more reporting-oriented commands.

Things To Keep In Mind

  • PML-TQ is tree-oriented, not sequence-oriented. The matched nodes may be structurally related without being adjacent in surface order.
  • Attribute names and node types are corpus-specific. A query written for one treebank may need adaptation for another.
  • Bound variables matter. They often represent the semantically important parts of the query.
  • Discontinuous matches are normal, especially for ancestor / descendant patterns.
  • When a query feels too broad, start with one node and one relation, then add more conditions gradually.

How To Build Queries Safely

A practical way to write PML-TQ queries is to proceed in small steps:

  1. Start with one simple node constraint, such as [upos="NOUN"].
  2. Bind it to a variable, such as $a := [upos="NOUN"];.
  3. Add one structural condition, such as child [...] or parent [...].
  4. Add nested or additional bound variables only after the simpler query works.

When To Use PML-TQ Instead Of CQL

Use PML-TQ when the pattern you care about is primarily structural:

  • a noun with a certain kind of modifier
  • a verb whose subject has certain features
  • a node with a descendant of a certain type
  • a relation between two named nodes in a syntax tree

Use a token-sequence language such as CQL when the pattern is mainly linear:

  • an adjective followed by a noun
  • a verb within three tokens of a noun
  • a phrase with optional intervening tokens
