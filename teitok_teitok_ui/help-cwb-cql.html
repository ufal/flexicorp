CWB/CQL Search Guide

CWB is the IMS Open Corpus Workbench, and CQL is its Corpus Query Language. It is a language for searching tokenized and annotated corpora: not only the written word forms, but also annotations such as lemma, part of speech, morphology, structural attributes, and named query results. For the full language, see the CQP manual.

Purpose Of CQL

CQL is used to describe corpus matches as patterns over tokens and annotations. A query can be as simple as a single word, but it can also describe sequences, alternatives, optional material, repeated patterns, structural restrictions, or named result sets that are reused later.

Typical uses include:

  • finding one word form or lemma
  • finding tokens with a certain annotation, such as upos="NOUN"
  • searching for multi-word sequences
  • grouping and counting results
  • storing a result set under a name and reusing it later

Basic Token Queries

The simplest query is a quoted word form.

"interesting"

This finds all occurrences of the word form interesting.

To search a token attribute explicitly, use square brackets.

[word="interesting"]
[lemma="struggle"]
[upos="NOUN"]

The available attribute names depend on the corpus. Common examples are word, lemma, upos, xpos, deprel, and corpus-specific morphological or structural attributes.

Regular Expressions

A regular expression is a compact way of describing a set of strings instead of writing every possibility separately. For example, instead of searching separately for interest, interests, interested, and interesting, you can describe them with one pattern.

"interest(s|(ed|ing)(ly)?)?"
[lemma="struggl.*"]
[word="colou?r"]

Some common regular-expression symbols are:

  • .: any single character
  • *: zero or more of the previous element
  • +: one or more of the previous element
  • ?: optional, zero or one
  • |: alternative, “or”
  • (...): group part of an expression together
  • [A-Z]: any character in a set or range

Examples:

  • [word="walk.*"] matches words beginning with walk
  • [word="colou?r"] matches both color and colour
  • [word="[A-Z].*"] matches a word beginning with a capital letter

If you want a character such as ?, +, or . literally rather than as a regular-expression symbol, escape it with a backslash.

"\?"
[word="C\+\+"]

CQP also supports flags after a regular expression. The most common are %c for case-insensitive matching, %d for ignoring diacritics, and %cd for both together.

"interesting" %c
[word="wahrung"] %cd

Combining Conditions On One Token

You can combine constraints on the same token with Boolean operators.

[lemma="struggle" & upos="VERB"]
[upos="NOUN" | upos="PROPN"]
[lemma!="be"]
  • & means both conditions must be true
  • | means either condition may be true
  • != means not equal

Boolean combinations can also be grouped with parentheses inside a token expression.

[lemma="bank" & (upos="NOUN" | upos="PROPN")]
[word="lead" & (xpos="NN" | xpos="VB")]

Negation can be written as a negative comparison.

[upos!="NOUN"]
[upos != "NOUN"]
[lemma="go" & upos!="VERB"]

Sequences, Gaps, And Repetition

Place token expressions next to each other to search for sequences.

[upos="ADJ"] [upos="NOUN"]
[lemma="take"] [lemma="place"]

For example, [upos="ADJ"] [upos="NOUN"] means “an adjective followed directly by a noun”, so it finds combinations such as green apples.

The empty token [] means “any one token”.

[lemma="struggle"] []
[upos="VERB"] []{0,3} [upos="NOUN"]

Parentheses can also group sequences outside token brackets, so that alternatives can range over more than one token.

( [upos="ADJ"] | [upos="ADV"] )
( [] | [] [] ) [lemma="go"]
( [lemma="take"] [lemma="place"] | [lemma="occur"] )

You can also add repetition operators after a token expression.

[upos="ADV"]? [upos="ADJ"] [upos="NOUN"]
[upos="ADJ"]* [upos="NOUN"]
[upos="ADJ"]+ [upos="NOUN"]
[lemma="take"] []{0,3} [lemma="place"]
  • ?: optional, zero or one time
  • *: zero or more times
  • +: one or more times
  • {0,3}: from zero to three times

Useful Search Examples

Adjective + noun:

[upos="ADJ"] [upos="NOUN"]

A lemma regardless of inflection:

[lemma="go"]

Proper names of one or more tokens:

[upos="PROPN"]+

A noun phrase with optional determiner and adjective:

[upos="DET"]? [upos="ADJ"]? [upos="NOUN"]

A verb followed within three tokens by a noun:

[upos="VERB"] []{0,3} [upos="NOUN"]

A token that must be a noun or proper noun, but only if the lemma is bank:

[lemma="bank" & (upos="NOUN" | upos="PROPN")]

Either a one-token or two-token lead-in before go:

( [] | [] [] ) [lemma="go"]

Named Queries

CQP can store a result set under a name and refer to it later. This is useful when you want to build a result once and then sort, count, group, tabulate, or filter it further.

NPs = [upos="ADJ"]* [upos="NOUN"];
ProperNames = [upos="PROPN"]+;

Once a named query exists, later commands can refer to that name instead of repeating the pattern.

Support for named queries depends on the backend and on corpus settings. Some environments allow only base search expressions and do not allow creating or reusing named results.

Grouping, Frequency Lists, And Tabulation

CQP also includes commands that operate on a result set rather than describing the initial match itself.

group

group groups a result set by one or more values and counts how often each group occurs.

group NPs match lemma;
group NPs match word by match lemma;

freq

freq produces frequency distributions over annotations. In many interfaces this overlaps with a dedicated frequency tab.

freq NPs lemma;
freq NPs upos;

tabulate

tabulate prints selected annotation values from a result set in table form.

tabulate NPs match word;
tabulate NPs match lemma, match upos;

These commands are often extremely useful, but they are not always permitted in every corpus interface. Depending on the backend, the corpus configuration, and the interface settings, sometimes only base queries are allowed, while commands such as group, freq, tabulate, and named-query reuse may be restricted or exposed through separate operations.

Structural And Advanced Commands

CQP can do more than token searching. It also supports structural attributes, aligned corpora, match labels, sorting, set operations, and additional scripting features. Not every interface exposes all of these directly, but they are part of the wider language family.

Things To Keep In Mind

  • Attribute names are corpus-specific. If upos or lemma does not work, check which annotations your corpus actually provides.
  • "go" searches the surface form, while [lemma="go"] searches the lemma.
  • Broad regular expressions can be expensive on large corpora.
  • Some interfaces accept only the core search expression, while others also allow named queries and result-set commands.
  • When in doubt, start with a small exact query and then generalize it.
