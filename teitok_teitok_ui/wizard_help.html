TEITOK Corpus Setup Wizard — Help

Companion to index.php?action=wizard. The wizard samples XML and surfaces TEITOK settings; it is meant to improve setup over time, not to certify a corpus as “perfect.”

Intent

  • Executive summaries and remedy links live in the wizard UI.
  • This page holds longer explanations, merge/write semantics, and optional URL overrides (Help page only).

Overview tab

Workflow order

This applies to any TEITOK corpus, not only spoken projects: ideally configure regions, flexicorp allowlists, and NLP pipelines (e.g. flexiPipe for parses you plan to query) before exporting or transcribing bulk TEI. No XML files in the sample yet is not an error — it can mean you are still in that preparation phase. The same guidance appears in the Overview panel of the wizard (not on the Spoken checklist).

Alignment tab — merge into settings

Only the Alignment tab performs a confirmed write: it merges missing alignment-related CQP entries into the corpus Resources/settings.xml (before each write, a daily backup is stored as backups/settings-YYYYMMDD.xml under the corpus root, one file per calendar day). Other tabs are read-only summaries.

Merge adds gaps detected from the sample: sentence s_tuid, token tuid/p_tuid when token ids appear in XML but no p-attribute is configured, and optionally text-level text_tuid. TEITOK then merges layers into tmp/cqpsettings.xml; reindex CWB/Pando after substantive changes.

Index(es) tab

This tab has no traffic-light dot in the wizard menu — it is diagnostic, not a “health score”. It runs python -m flexicorp info backends (via TEITOK helpers) to list which backend routes flexicorp considers reachable for this corpus, compares defaults/flexicorp/backend to that overview (plus tt_flexicorp_pando_status when the default is pando), calls flexicorp info corpus on the primary backend, compares merged CQP settings to the sampled XML, and for CWB-style backends runs capped flexicorp freq calls to estimate distinct types per token attribute and selected registry structural fields.

Vocabulary numbers are approximate: freq returns a capped group table; values ending in ≥12000 hit the wizard cap. Non-CWB primaries (e.g. ClickHouse) skip freq here.

Default flexicorp backend

defaults/flexicorp/backend (getset) selects which flexicorp backend handles queries. Empty means flexicorp’s default. Changing backend may require matching index/tooling on the server.

Indexed corpus (CWB)

The wizard looks for word.corpus under cqp/ using cqp/defaults/registry. If TEI exists but no index is present yet, encode/reindex after CQP settings match your TEI (regions, p-/s-attributes).

Spoken data (TEITOK ↔ flexicorp)

Spoken data in TEITOK allow the audio of the text to be used, typically with alignment between the transcription and the audio at the level of the utterance or even the token. With the proper set-up, aligned spoken data do not only present playable audio above the text, but also an aligned view in WaveSurfer, which displays the transcription synchronized with the audio, and in search results the audio of each resulting utterance can directly be listened to. Audio can also come from a video file, in which case the video is displayed as well.

The wizard shows one checklist: XML expectations (what TEI should contain — fixes are per file), project/index lines (where TEITOK can be adjusted), short notes in the UI, and longer explanations here via row Help links. Corpus-wide workflow order (configure CQP/flexicorp/pipelines before bulk TEI) is on the Overview tab, not repeated here.

Default backend and CWB word.corpus status live on the Index(es) tab (backend, indexed corpus). The Spoken checklist focuses on oral TEI and playback/search behaviour — not index prerequisites.

Media pointers

TEI should reference audio or video via media/@url and/or header <media>. Relative paths usually resolve against an Audio/ folder beside index.php.

Indexed corpus (TEITOK cqp.php / settings.xml): spoken corpora usually expose media URLs as utterance-level structural fields — nested under region u in <sattributes> — so multiple segments or files per TEI document stay aligned with ⟨u⟩ (e.g. ParCzech uses chunk_url). Other setups use nested fields named media or u_media. Older corpora may use nested text_media under region text, or a top-level region audio with xpath/href. The wizard treats these patterns as wired when the corresponding items appear in merged tmp/cqpsettings.xml or canonical Resources/settings.xml.

Unreleased flexicorp search UI (flexicorp.js, getHitAudioInfo) aligns with TEITOK by preferring XML in the hit context for the “sound” control: URLs and timing on <media>, <recording>, <u>, @chunk_url, and ancestors. Flexicorp should follow established corpus conventions — not replace them — except where flexiTools deliberately changes behaviour.

Illustrative pattern (region u with a URL field — names follow your project):

<cqp corpus="..." searchfolder="xmlfiles">
	<sattributes>
		<item key="u" ...>
			<item key="chunk_url" xpath="..." href="..."/>
			...
		</item>
	</sattributes>
</cqp>

The wizard checks merged tmp/cqpsettings.xml when present, otherwise corpus Resources/settings.xml. After edits, reindex so CWB/Pando materializes the fields you declared.

Two timeline rows: utterance (TEI sample hint vs index-backed bounds) and token (TEI-only refinement).

Utterance timeline (⟨u⟩)

This wizard’s primary role is to help you get Resources/settings.xml right so the corpus search index exposes utterance time bounds as CQP structural u / u_start / u_stop after encoding and reindex. That index wiring is what deployed TEITOK and flexicorp rely on for utterance-scoped snippets, playback scope, and search—not raw TEI alone. The hard check and Wizard fix for a missing utterance region live under Utterance region (CQP); fix settings, complete xpath mapping under TEITOK CQP / Index(es), then reindex.

The Utterance timeline (⟨u⟩) checklist row is a small extra: it samples TEI for <u> with @start and @stop or @end as a quick signal that transcripts may carry inline times. That XML signal is optional sugar while you transcribe; it does not replace the obligation to declare and materialize utterance regions in CQP settings so u_start / u_stop (or region u) exist in the index. When times are missing in the sample, the row may show Review even though index configuration remains the decisive step.

Token timeline (⟨tok⟩)

Token-level times (<tok> with @start and @stop or @end) are only checked in XML here. They are refinements for the client JS (e.g. WaveSurfer word-level sync): they do not have the same index obligation as utterance bounds. You can have utterance times in the index without token times in TEI, or the reverse for experiments — but word-level UI polish expects token times in the files when you need them.

WaveSurfer (wavesurfer.php / wavesurfer.js)

The WaveSurfer page reads XML from disk for one document (not the flexicorp search pipeline). Settings used there include:

  • xmlfile/defaults/speechturn — utterance element name (default U → <u>); URL/query override utt.
  • xmlfile/speech/highlight — region/tier WaveSurfer aligns the waveform to (URL/query alt); if unset and //tok[@start] exists in the file, TEITOK defaults to token highlighting (TOK), otherwise the utterance tag.
  • xmlfile/speech/showsubtitles, xmlfile/speech/showspeaker — optional UI (also URL subtitles, speaker).
  • defaults/media/type — when inline, TEITOK can fold inline <media> into paging; interacts with xmlfile/speech/paged.
  • defaults/media/baseurl / defaults/base/media — base path for resolving relative media URLs.
  • defaults/media/skipempty — seconds threshold to offer “play from start of transcription” when leading silence is long.
  • defaults/media/spectogram — enables spectrogram plugin (loaded when non-empty).
  • xmlfile/paged/element — when set to media, enables page nav tied to media fragments.

WaveSurfer expects utterances used as editing regions to carry a unique @id; missing ids trigger a warning in edit mode. Corpus/view allttag still applies elsewhere (flexicorp); WaveSurfer primarily follows xmlfile/speech/highlight / auto-detect as above. Token @start/@stop in TEI refine word-level sync in the browser; utterance-level timing for scope still comes from the index in search.

TEITOK native CQP (cqp.php) — playback column

Beyond nested URL fields, TEITOK may mark a structural region so results include an indexed audio path and timing for the native play button: for each entry in cqp/sattributes, if $satt['audio'] is set, cqp.php adds , match <region>_audio to tabulate and wires play buttons using xidx snippets plus defaults/playbutton (or shared/local play GIF fallbacks). Context hits use cqp/defaults/searchtype, cqp/defaults/subtype, cqp/defaults/context/kwic, and optional cqp/sattributes/<subtype>/contextatts for markup colouring — overlapping checks already appear under default snippet scope / subtype rows.

Utterance region (CQP)

Utterance time bounds used for search and snippet scope are read from the index via structural regions: most corpora use a single region u aligned with TEI <u>, or paired bounds u_start and u_stop. The wizard treats u or both u_start and u_stop as a wired utterance layer (merged tmp/cqpsettings.xml when present, plus TEITOK getset at runtime). Configure under corpus CQP settings, then reindex. This is separate from token-level @start/@stop on <tok>, which stay in TEI for JS refinements.

Search context regions

Corpus setting flexicorp/context_scope_regions (TEITOK getset, mirrored in Resources/settings.xml as flexicorp item key="context_scope_regions") controls which structural regions search may use for context/KWIC scope: comma- or space-separated region ids, or empty / - / default for the built-in default list — the same list flexicorp.php resolves for implicit values. An explicit list that omits u conflicts with spoken XML — search cannot expand hits to utterances. The Spoken-tab wizard can append u to an explicit list, or write the built-in default list as an explicit value when the setting is still implicit.

Audio folder & uploads

For relative media paths, expect an Audio/ directory beside index.php and a TEITOK file-upload definition in Resources/settings.xml under <files>, e.g. <item key="audio" folder="Audio" … />. The extension attribute is optional; when present it should list allowed suffixes (comma-separated, often *.mp3, *.wav, *.ogg, or *.mp4 for video) so TEITOK only accepts those uploads—matching how browsers expose audio/video MIME types. Absolute media URLs may not need a local folder.

TEITOK default snippet scope

cqp/defaults/searchtype and cqp/defaults/subtype set the default hit snippet shape in TEITOK and flexicorp. searchtype=context with subtype=u opens utterance-wide, listenable snippets by default; KWIC/sentence defaults suit dependency trees and require users to widen scope for long audio snippets.

CQP defaults vs indexed subtype

If the default subtype names a region that is not in the indexed s-attributes list, fix TEITOK CQP configuration before expecting flexicorp to mirror that scope.

Oral context vs sentence default

If the sample has <u> but defaults fix context on <s>, hits open sentence-sized context — often wrong for listening-sized playback. Prefer context + subtype=u for spoken material.

Sentence vs utterance ambiguity

When both <s> and <u> appear and defaults leave subtype unset (or token-wide), flexicorp may fall back to token-window scope. Set explicit TEITOK defaults so native CQP and flexicorp agree.

Other CQP default checks

See cqp/defaults/* in the CQP editor; merged tmp/cqpsettings.xml reflects TEITOK merges.

Dependencies tab

The tab is organized like Spoken data: sectioned rows, XML (sample) vs Project / index, and short Notes with links. It covers dependency arcs (deprel/head in TEI, in CQP pattributes, and optionally in xmlfile/pattributes for the XML editor), sentence regions (<s> in TEI, region s in CQP, <s @tuid> and CQP s_tuid), default hit shape (TEITOK cqp/defaults — sentence-sized context vs KWIC is what native tree views and deptree.php-style UIs expect), optional UD morphology (upos, xpos, lemma, feats), plus corpus TEI folder and flexicorp index reachability. It does not list PHP module dependencies. Full backend / freq tables: Index(es).

UD token arcs (deprel / head)

TEI should carry deprel and head on <tok> (or <w>) for Universal Dependencies–style trees. CQP <pattributes> must list the same keys with xpath so the encoded corpus indexes them. xmlfile/pattributes in Resources/settings.xml controls which token attributes the TEITOK XML editor exposes—align it with your TEI for hand-editing.

Sentence ⟨s⟩ & sentence ids

Dependency tools usually need a sentence region in TEI and a matching structural region in CQP s-attributes. Stable <s @tuid> (or your project’s sentence id) plus a nested s_tuid (or tuid) field under the sentence region in CQP keeps XML, index, and parallel-alignment flows aligned.

Search hits & dependency trees

cqp/defaults/searchtype and subtype set the default snippet shape. KWIC or explicit context + subtype=s suit sentence- or token-window trees; context + subtype=u is for long spoken snippets. TEITOK’s dependency tree view (deptree.php in a typical install) reads the same indexed attributes—if defaults leave subtype unset while both <s> and <u> exist, fix defaults so hit scope is predictable (see sentence vs utterance).

Optional UD morphology

For standard UD corpora, also index upos, xpos, lemma, and feats in CQP and expose them in xmlfile/pattributes when editors should touch them.

Corpus folder & flexicorp index

The wizard checks that the TEI directory resolves, the flexicorp CLI bridge loads when available, and the default backend maps to an encoded corpus—see Index(es) for detail.

Alignment runtime (flexicorp)

Parallel hits expose aligned_counterpart when backends pair rows. Sentence s_tuid is the usual baseline; token tuid/p_tuid enable finer highlighting when ids exist in XML. Depalign uses sentence-level ids; flexicorp may derive sentence ids from token ids when they share a prefix pattern. text_tuid on region text is optional for whole-parallel-text queries.

Environment overrides (URLs)

The wizard assumes the standard TEITOK corpus UI: corpus admin is index.php?action=adminsettings (core TEITOK module), with in-page anchors such as #cqp and #flexicorp. It does not support alternate admin routes via environment variables — non-standard layouts should be edited manually.

  • TEITOK_WIZZARD_HELP_URL — this page or another help URL (wizard Help button).
  • TEITOK_CQP_SETTINGS_URL — optional override for links to the CQP / indexed-attributes area. If unset, the wizard uses index.php?action=adminsettings#cqp (not the nonstandard action=cqpmng route).
  • TEITOK_METADATA_URL — metadata / encoding profile route (default index.php?action=metadata).
