CWB CQL on a pando index

With this choice you write your query in CWB CQL, the language of the IMS Open Corpus Workbench (CQP), and pando runs it on its own index. Most token queries work exactly as in CQP. The language itself is explained in the CWB/CQL search guide; this page lists only what to write differently for pando.

Works as in CQP

  • Token queries: "word", [lemma="go" & upos="VERB"], [], sequences, ? * + {m,n}, !=, ! inside [ ].
  • Regular expressions and escapes: [word="walk.*"], [word="\."], "\(" or "[(]" for a literal bracket.
  • Flags %c, %d, %cd, %l.
  • Document metadata with ::, as the query builder writes it: [lemma="go"] :: match.text_genre="Book" within text; named tokens a:[…] b:[…] :: a.lemma != b.lemma.
  • The token's own metadata: [lemma="go" & _.text_genre="Book"].
  • XML tags: <s> [upos="DET"], [] </s>, <text_genre="Book"> [].
  • The target marker @[upos="NOUN"], implication [(lemma="be") -> (upos="AUX")], lookahead [upos="DET"] [:upos="NOUN":].
  • within s, within text.
  • Named queries with count by, group by, sort by, size, cat, tabulate.

Working on result sets

The largest difference with CQP: pando does not combine or rework stored results. subset, intersect, union, diff, join, meet / MU, reduce, randomize and piping output to a program (cat A > "| sort") are CQP commands that pando does not read. Put all conditions into one query instead (with within, :: and named tokens), and use the Frequency and Download options of this page for what you would pipe to a script.

Write these differently

For these, switch the query language to pando CQL and write the right-hand form.

CQPIn pando CQL
Alternative sequences
( [] | [] [] ) [lemma="go"]		two queries, or Manatee CQL, which reads it
A number of tokens
[lemma="go"] []* [lemma="home"] within 5		[lemma="go"] []{0,3} [lemma="home"]
Limiting the hits
A = [lemma="go"] cut 100		A = [lemma="go"]; cat A 0 99
Words near each other
MU(meet [lemma="a"] [lemma="b"] s)		[lemma="a"] []* [lemma="b"] within s (in this order)

Patterns of varying length (?, +, {m,n}) can give more hits than in CQP: CQP keeps one match per end ([upos="DET"]? [upos="NOUN"] counts each noun once), pando also counts the shorter match.

The full list, with what pando reads differently from CQP, is on the CWB dialect page of pando. The pando CQL guide explains pando's own language.
