BCQL Search Guide

BCQL is the BlackLab Corpus Query Language, also referred to in some BlackLab documentation as CorpusQL. It is a corpus-search language for tokenized corpora with annotations, spans, inline tags, and optionally indexed relations. It is similar in spirit to CQL-family languages, but it also includes BlackLab-specific features such as XML-style span queries, captures, and relation-oriented patterns.

Purpose Of BCQL

BCQL is used to describe matches over annotated text. A query can search for one token, a sequence of tokens, a match restricted to a span such as a sentence, a span containing another match, or, when the corpus supports it, structural relation patterns.

Typical uses include:

  • finding one word form or lemma
  • searching token annotations such as word, lemma, or pos
  • searching token sequences with gaps and repetition
  • restricting matches with spans such as <s/>
  • capturing named parts of the match
  • searching indexed relations such as dependencies, if the corpus was indexed with them

Basic Token Queries

A BCQL query often starts with either a quoted token or a token expression in square brackets.

"interesting"
[word="interesting"]
[lemma="go"]
[pos="N.*"]

Quoted strings search a token form directly. Bracket expressions search an annotation value explicitly. The actual annotation names depend on the corpus, but common ones include word, lemma, pos, and corpus-specific fields.

Regular Expressions

Regular expressions can be used inside token constraints.

[word="walk.*"]
[lemma="struggl.*"]
[pos="N.*"]

Examples:

  • [word="colou?r"] matches both color and colour
  • [word="[A-Z].*"] matches a token beginning with a capital letter
  • [lemma="go|come"] matches either lemma

Combining Conditions On One Token

You can combine conditions with Boolean operators inside one token expression.

[lemma="go" & pos="V.*"]
[pos="N.*" | pos="PROPN"]
[lemma!="be"]
  • & means both conditions must hold
  • | means either condition may hold
  • != excludes a value

Sequences, Gaps, And Repetition

Place token expressions next to each other to search for sequences.

[pos="ADJ"] [pos="N.*"]
[lemma="take"] [lemma="place"]

The empty token [] means “any one token”. Quantifiers can be used after token expressions.

[lemma="take"] []{0,3} [lemma="place"]
[pos="ADV"]? [pos="ADJ"] [pos="N.*"]
[pos="ADJ"]* [pos="N.*"]
  • ?: optional
  • *: zero or more
  • +: one or more
  • {m,n}: between m and n repetitions

Spans And XML-Style Tags

One of the more characteristic BCQL features is span querying with XML-style syntax. If your corpus indexed spans such as sentences, paragraphs, named entities, or speech segments, you can query those directly.

"de" within <s/>
"test" within <speech/>
<ne type="PERS"/>

Examples like these mean:

  • a token or pattern inside a sentence span
  • a token or pattern inside another indexed span
  • a whole span with a given name, optionally constrained by attributes

Within, Containing, And Overlap

BCQL supports positional operators between matches.

"you" "are" within <s/>
<s/> containing "grass"
"cow" within (<pasture/> containing "grass")

These let you filter one pattern by another span or enclosing match. This is especially useful when sentence, paragraph, chapter, or named-entity spans have been indexed.

Captures

BCQL can capture parts of the match under a name so they can be reused or inspected later.

A:[]
"big" A:[]
PERSON:[lemma="john|mary"]

BlackLab also supports capture constraints after ::, for example to compare captured values.

"big" A:[] "or" "small" B:[] :: A.word = B.word

This means: capture two tokens and require that the captured annotation values satisfy the constraint.

Relation Queries

If the corpus was indexed with relations, BCQL can search relation targets directly. This is the part of BCQL that matters for dependency-style searching.

_ -nsubj-> _
_ -obj-> [lemma="book"]

These patterns describe relations rather than only surface token sequences. In practice, they are only available when the corpus actually indexed relations. If the corpus contains only token annotations such as deprel as plain fields, but no indexed relations, then relation-style BCQL is not available even though ordinary token search still is.

Useful Search Examples

A word form:

"interesting"

A lemma regardless of inflection:

[lemma="go"]

An adjective followed by a noun:

[pos="ADJ"] [pos="N.*"]

A phrase with up to three intervening tokens:

[lemma="take"] []{0,3} [lemma="place"]

A match inside a sentence span:

"de" within <s/>

A relation query over an indexed dependency relation:

_ -nsubj-> _

Things To Keep In Mind

  • Annotation names are corpus-specific. One corpus may use pos, another upos, another something else.
  • Span queries such as within <s/> only work if the corpus indexed those spans.
  • Relation queries only work if relations were indexed structurally, not merely stored as token attributes.
  • Captures and capture constraints are powerful, but more advanced than plain token-sequence querying.
  • When in doubt, start with a simple token query and then add spans, captures, or relations step by step.
